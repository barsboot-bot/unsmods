# Unesennye v2

Переписанный мод Unesennye для DayZ (целевая версия 1.24+). Воспроизводит полный набор v1.2.0:
машинное радио, портативные музыкальные карты с альбомами и общий реестр треков.
Комментарии и интерфейс — на русском.

> **Статус: не скомпилировано.** Код написан и проверен статическими инструментами и тестами в этом репозитории,
> но **не собран в Workbench** и **не запускался на сервере**. Всё, что помечено в разделе
> «Что не подтверждено», нужно проверить при первой сборке.

## Состав

| Папка | Что внутри | Где грузится |
|---|---|---|
| `@unesennye_music_db/` | Протокол (`UnsProto`), реестр треков (`UnsRegistry`), класс карты, действия, `config.cpp` (генерируется) | клиент и сервер |
| `@unesennye_servermod/` | Рукопожатие, проверка запросов, состояние проигрывания, рассылка | только сервер |
| `@unesennye/` | Рукопожатие с таймаутом, блокировка без серверного мода, воспроизведение | только клиент |
| `tools/tracks.json` | Манифест треков и альбомов. Единственный источник правды | — |
| `tools/build_config.py` | Генерирует `@unesennye_music_db/config.cpp` из манифеста | — |
| `tools/check_scripts.py` | Статические проверки скриптов (см. ниже) | — |
| `tests/` | Тесты генератора и проверяльщика (`unittest`, 33 теста) | — |

## Ключевые решения

- **Один реестр треков.** Каждый трек имеет стабильный целочисленный `trackId` и класс `Track_<id>` (например, `Track_001`).
  Альбомы ссылаются на треки по `trackId`, а не по имени. В v1 из-за этого возникало несоответствие имён и позиций.
- **Альбом — это вложенные классы-слоты**, а не массив: `class Slot01 { track = 7; };`. Число треков в альбоме
  (`trackCount`) и порядок задаются только в манифесте.
- **Один RPC-ID (`91337`)** с кодом операции первым аргументом. Диапазон вне ванильных ERPC и вне v1 (100–204, 300–305, 400–406).
- **Сервер проверяет каждый аргумент и меняет состояние только после всех проверок.** Отказ уходит клиенту как `S2C_REJECT` с кодом причины.
- **Клиент не проигрывает звук сам.** Действие лишь отправляет запрос. Звук запускается по `S2C_PLAY`, который рассылает сервер.
- **Действия (`ActionSingleUseBase`) и класс карты лежат в общем моде.** Так `SetActions` видит одна и та же логика
  на обоих концах, без дублирования имён между клиентом и сервером.
- **Аудио (`.ogg`) не коммитится.** См. `.gitignore`. Пути в `config.cpp` указывают на `data/sounds/tracks/<file>`.

## Протокол

Все сообщения идут через `ScriptRPC` с `RPC_ID = 91337`. Первый `Int` — код операции.

| Код | Направление | Аргументы | Назначение |
|---|---|---|---|
| 1 `C2S_HELLO` | клиент → сервер | `proto:int`, `nonce:int` | рукопожатие |
| 2 `C2S_CAR_PLAY` | клиент → сервер | `lo:int`, `hi:int` | следующий трек машины |
| 3 `C2S_CAR_STOP` | клиент → сервер | `lo:int`, `hi:int` | остановить музыку в машине |
| 4 `C2S_CARD_STEP` | клиент → сервер | `lo:int`, `hi:int`, `dir:int` (±1) | следующий / предыдущий трек карты |
| 5 `C2S_CARD_STOP` | клиент → сервер | `lo:int`, `hi:int` | остановить музыку карты |
| 101 `S2C_HELLO_ACK` | сервер → клиент | `nonce:int`, `ok:int` | подтверждение протокола |
| 102 `S2C_PLAY` | сервер → все | `key:string`, `x,y,z:float`, `trackId:int`, `kind:int` | запустить звук |
| 103 `S2C_STOP` | сервер → все | `key:string` | остановить звук |
| 199 `S2C_REJECT` | сервер → клиент | `reason:int` | отказ |

Причины отказа (`UnsProto.R_*`): 1 протокол, 2 нет рукопожатия, 3 кулдаун (1 с), 4 неверная цель, 5 не в машине,
6 карта не у игрока, 7 нет треков.

Ключ `key` — `GetNetworkIDString()` машины или карты. Один источник звука на ключ: новый `PLAY` заменяет старый.

## Рукопожатие

1. Клиент каждые 500 мс проверяет, есть ли игрок. Когда появляется, отправляет `HELLO` один раз.
2. Таймаут 4000 мс отсчитывается **от отправки `HELLO`** (в v1 таймаут сравнивался с секундами).
3. Сервер при совпадении `PROTO_VERSION` отвечает `HELLO_ACK` с тем же `nonce`.
4. Без ответа за 4 с клиент останавливает звук, показывает сообщение и вызывает `GetGame().Disconnect()`.

Ограничение: рукопожатие подтверждает **наличие мода**, а не личность клиента. Секрета нет; всё, что клиент может
подделать, сервер перепроверяет (см. ниже). Это сознательный выбор, а не защита.

## Валидация на сервере

- Все `Read` проверяются; при ошибке чтения запрос отбрасывается.
- Кулдаун 1 с на сессию.
- Машина: объект должен быть `Transport`, игрок должен сидеть в нём (`GetCommand_Vehicle().GetTransport()`), а не в радиусе.
- Карта: объект должен быть `UnesennyeMusicCard_Base`, а `GetHierarchyRootPlayer()` — тот же игрок. Альбом берётся
  из конфига класса карты, а не из запроса.
- Шаг карты: `dir` должен быть ровно `+1` или `-1`.
- Состояние (`m_CarOrdinal`, `m_CardIndex`) меняется только после прохождения всех проверок.

## Сборка и проверка (до запуска в Workbench)

```bash
cd unesennye-v2
python3 tools/build_config.py --check          # валидация манифеста
python3 tools/build_config.py                  # генерация @unesennye_music_db/config.cpp
python3 tools/build_config.py --strict-audio   # то же, но падать при отсутствии .ogg
python3 tools/check_scripts.py                 # статические проверки скриптов
python3 -m unittest discover -s tests -v       # тесты
```

`check_scripts.py` проверяет:
1. повторные объявления верхнего уровня (классы, enum, глобальные функции) в разных файлах (`modded class` не считается);
2. баланс фигурных скобок;
3. `delete` (владение — через `ref`);
4. запрещённые API из раздела «Что не подтверждено» (`ConfigReadString`, `RegisterServerRpc`, `ParamWriteBuffer` и др.);
5. `CallLater(this, ...)` — нужен `CallLaterByName`;
6. `modded class UnesennyeX` без базового объявления.

Это эвристика по тексту, а не парсер Enforce. Она не заменяет компиляцию.

## Установка на сервер

1. Положить `.ogg` в `@unesennye_music_db/data/sounds/tracks/` (имена — как в манифесте).
2. Собрать PBO из трёх папок (Workbench / DayZ Tools). Имя аддона — имя папки без `@`.
3. Клиент: `-mod=@unesennye_music_db;@unesennye`
4. Сервер: `-servermod=@unesennye_music_db;@unesennye_servermod`

Без `@unesennye_music_db` ни один из модов не загрузится: они зависят от него через `requiredAddons`.

## Добавление треков и альбомов

1. Отредактировать `tools/tracks.json`. Новый трек — новый уникальный `id` (1–999). Альбом — `id` вида `Album01`
   и до 20 `trackId`.
2. `python3 tools/build_config.py --check`, затем `python3 tools/build_config.py`.
3. Положить `.ogg` с именами из `file`.
4. Пересобрать PBO.

`config.cpp` редактировать вручную не нужно и нельзя — он перезаписывается генератором.

## Что исправлено относительно v1

| Находка ревью | Как решено в v2 |
|---|---|
| Альбом не доходил до клиентов (404 без слушателя) | `S2C_PLAY` рассылается всем, слушатель есть |
| Таймаут рукопожатия сравнивался с секундами | Таймаут в миллисекундах, от отправки `HELLO` |
| Нет повтора после `OnAuthFail` | Повторяющийся тик; состояние не «застревает» |
| Кулдаун съедался при вставке карты | Кулдаун только на сервере, на сессию |
| Разные типы параметра обработчика (`ParamReadBuffer` / `ParamsReadContext`) | Единый `ParamsReadContext` |
| Несовпадение ID треков (позиционные имена) | Стабильный `trackId`, один реестр |
| Состояние менялось до проверки | Проверки первыми, состояние после |
| Детерминированный токен | Нет токена; рукопожатие — только проверка протокола |
| Ручные `delete` | Нет `delete`; проверяется `check_scripts.py` |
| Дублирование имён клиент/сервер | Общие типы только в `UnsProto`/`UnsRegistry` |
| Конфиг через несуществующие функции | `GetGame().ConfigGet*` (см. ниже) |
| Проигрывание без подтверждения сервера | Клиент слушает только `S2C_PLAY` |
| `CfgMods` без блока `defs` во всех трёх config.cpp v1 (пропущено в ревью) | В v2 указаны `defs` с `gameScriptModule` / `worldScriptModule`; подтвердить в Workbench |

## Что не подтверждено (проверить в Workbench)

Ниже — вызовы, которые не нашлись в документации или исходниках, которые я смог просмотреть. Для каждого есть
короткий тест, который поймает ошибку при первой сборке.

- `GetGame().GetTime()` возвращает `int` (миллисекунды). Иначе — привести тип.
- `PlayerIdentity.GetPlayerId()` существует и уникален на сессию.
- `GetGame().GetPlayers(array<Man>)` существует.
- `ScriptInvoker.Insert/Remove` принимает глобальную функцию (`UnsClientOnRPC`, `UnsServerOnRPC`).
- `PlayerBase.MessageStatus(string)` существует. Иначе — заменить на `Print` и своё уведомление.
- `GetGame().Disconnect()` существует.
- `Transport` — базовый класс `CarScript` (нужно для `Transport.Cast`).
- `CCINone`, `CCTNone`, `CCTNonRuined(UAMaxDistances.DEFAULT)` — допустимые условия.
- `ActionSingleUseBase` — допустимый базовый класс для действий над целью без предмета в руках.
- `Math.RandomInt(min, max)` существует.
- `int.ToString()` доступен в Enforce.
- `EffectSound.SetAutodestroy(true)` и `EffectSound.Stop()`.
- `CfgMods`: `dir` без `@` (как в исходном репозитории), `dependencies[]` и `defs`. Проверить при сборке PBO.
- Вызовы конфига: `GetGame().ConfigGetInt/ConfigGetText/ConfigGetChildrenCount/ConfigGetChildName/ConfigIsExisting`.
  В исходниках dayzexplorer (`liquid.c`, `dayzgame.c`) эти функции вызываются как члены `CGame`.
  В wiki те же функции описаны как глобальные. Если Workbench не примет форму `GetGame().`, поменять во всех местах
  (`UnsRegistry.c`) одним поиском.

Не подтверждено: `RPCRegisterServer` / `RPCRegisterClient` в v2 не используются. Регистрация идёт через
`Event_OnRPC`, которое подтверждено по wiki и примерам.

## Ограничения

- Нет UI-виджетов: управление через действия (контекстное меню). Предыдущий v1 UI не переносился.
- Машинный плейлист общий для всех машин по порядку `id` (`carPlaylist = 1`). Выбор конкретного трека не реализован.
- Сессии и состояние проигрывания хранятся в памяти и сбрасываются при перезапуске сервера.
- Очистка сессий при отключении игрока не реализована; для небольшого сервера это безвредно, но растёт со временем.
- Звук слышен всем клиентам; громкость и дальность задаются в манифесте (`volume`, `range`).

## Поправка к ревью v1

В отчёте `REVIEW_unesennye.md` (вне репозитория) было два уточнения:
1. Я писал, что функции конфига вызываются «standalone». Исходники dayzexplorer показывают вызовы через `GetGame().` / `g_Game.`.
   Это меняет только форму вызова, но не выводы про несуществующие функции (`ConfigReadString` и др.) в v1.
2. В v1 `CfgMods` не содержит блока `defs`. Без него скрипты мода могут не загружаться. Я не включил это в отчёт, а
   в v2 блок `defs` есть. Проверить в Workbench: если скрипты v1 грузятся без `defs`, пункт снимается.
